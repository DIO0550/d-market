# Hearing Patterns - Feature Spec & PRD

## Common (Both Formats)

**Batch 1: Basics**
- What is the feature / product name?
- What problem does it solve? (1-2 sentences)
- Who are the target users?
- What is in scope / out of scope?

## Feature Spec Hearing

**Batch 2: User Requirements**
- What are the main user stories? (As a... I want to... So that...)
- What are the key screens / UI elements?
- What are the validation rules?
- Are there business rules or constraints?

**Batch 3: Technical & Quality**
- What data needs to be stored or processed?
- What are the error handling requirements?
- Non-functional requirements? (performance, accessibility)
- Dependencies on other features / systems?

## PRD Hearing

**Batch 2: Product Context**
- What is the current state / pain point? (quantify if possible)
- What does success look like? (metrics / KPIs)
- What are the user personas and their key needs?
- Any competitive context or constraints?

**Batch 3: Solution & Scope**
- What is the proposed solution at a high level?
- Are there phases or MVP vs. full scope?
- What are the risks and open questions?
- Any timeline or launch constraints?

## Section Adaptation Rules

- No UI → skip Screen/UI Specification sections
- No data persistence → skip Data Model / ER diagram
- Simple feature → simplify State Diagram or omit
- No external dependencies → skip Dependencies section
- PRD: If no go-to-market plan → skip that section
- PRD: If no competitive analysis needed → skip that section
